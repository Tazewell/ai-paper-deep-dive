# Research Idea 与相关工作核查

仅在用户想提出/评价科研创新、判断是否有人做过、制定研究计划时额外使用。

## 先建立可检索的技术主张

将 idea 改写成一句可证伪的假设，例如：“在固定训练 FLOPs/文本数据和模型参数规模时，仅改变视觉 token 的存在会对低频词准确率产生不成比例的影响。”

拆为三块：
- **科学假设**：可证伪、与结果变量直接有关；不是空泛提升性能。
- **技术实现**：真正不同于已有方法的机制，分清单纯组合与新的问题设定。
- **评测设计**：基线、控制变量、指标、负对照与失败阈值。

## 相关工作查重流程

1. 从核心机制、替代术语、同义现象、对立结论四种方向搜索。
2. 找原论文与官方代码；按时间排列并明确预印本日期和更新版本。
3. 对每个近邻工作，比较**问题设定、干预变量、具体机制、训练数据/规模、主要证据**，避免只按论文标题比较。
4. 对最接近的 3–8 篇论文建立差异表。找出**最强反例**而不是只找支持 idea 的工作。
5. 给出审慎判断：已覆盖 / 部分重叠 / 可能留白 / 证据不足；不得仅因搜索没找到就下结论“首创”。

## 最小实验（推荐计算资源有限的研究生）

- **主假设**：H1 和与其竞争的 H0（替代解释）。
- **最小设置**：小模型、公开数据、相同 tokenizer / compute / data 与 seeds（依问题调整）；先用 1–2 天 smoke test 确认 signal，再扩大。
- **必要 Baselines**：真实 SOTA 中最近邻方法 + 最简单基线 + 算力匹配基线。
- **消融实验**：至少移除一个核心组件，并加入针对最强替代解释的负对照。
- **指标**：主指标 + 副作用指标 + 显存、吞吐、成本；尤其区分整体均值与长尾子群。
- **止损标准**：预先描述什么结果会否定假设，避免只做 cherry-picking。
- **资源估算**：若用户提供 GPU 型号/卡数/显存，则给出**粗估范围、显存瓶颈和不确定性**；没有足够信息时不要承诺一定训练得动。

## Idea 审核报告简表

| 维度 | 要回答的问题 |
| --- | --- |
| 新颖性 | 最近邻工作是谁？真正不同的点是什么？ |
| 正确性 | 是否依赖错误的数学或工程前提？ |
| 可验证性 | 什么实验可以区分假设和替代解释？ |
| 科学价值 | 如果结果为真，会改变什么认知？ |
| 工程价值 | 是否能改善性能、成本、可靠性或可解释性？ |
| 可行性 | 数据、训练/推理资源、开源代码是否足够？ |
| 风险 | 哪些消融结果会让该 idea 不再成立？ |

报告末尾给出具体 Next experiment（最先跑的一组实验），而不是只给方向口号。
