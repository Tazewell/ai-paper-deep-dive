# 每篇论文独立归档：Markdown / HTML

## 触发与交付（默认自动运行）

- **自动启动，无需提示：** 当用户给一篇论文要求完整精读、跟读、逐章节阅读或产出研究笔记，就同时创建该论文真实的 Markdown `.md` 和 HTML `.html` 文件。无需请求是否导出、无需用户补说“生成文档”；除非用户明确禁止文件导出。
- **何时交付：** 本轮精读讲解结束前，先完成 `.md`，然后立刻用转换脚本生成 `.html`，验证二者存在，再在回复末尾附两个有效下载链接；不要先仅答复正文、把导出留到下一轮。
- **逐章节精读：** 第一节开始后即自动制作阶段性 MD+HTML。顶部标 `状态：进行中`，逐节累计已有证据，显式列出未读章节；同一会话有可访问的现有笔记时持续更新同一篇，重新渲染 HTML。精读完成后改为 `状态：已完成`。不把尚未精读的部分捏造成完成内容。
- **单点问题例外：** 在没有正在进行的整篇/章节精读任务时，用户只问一个概念、公式、一个训练细节，可直接回答，不必自动建立新论文文件。如果明确在既有论文精读进程中则尝试更新阶段笔记。
- **每篇论文独立：** 不将不同论文混进同一 MD 文件；涉及多篇则各生成一组，用户请求比较时可另有一份对比稿。
- **无文件能力时：** 明确告知无法生成实文件，并给可复制 Markdown，不得捏造 sandbox 链接或声称已完成。不可承诺在后台自动更新；后续会话需要先确认论文或已有笔记是否可访问。

## 命名规范

优先：`<arxiv-id>_<short-slug>_notes.md`（如 `2304.08485_llava_visual_instruction_tuning_notes.md`），HTML 对应同名 `.html`。无法确认 arXiv id 时用年份、第一作者和短标题作为唯一名前缀，并避免覆盖不同版本。文件名仅用小写英文字母、数字、下划线、连字符和点。不同论文各自单独文件；多篇对比任务可另外生成比较笔记。

## Markdown 内容规范（按实际需要调整）

```markdown
---
title: "论文完整标题"
authors: "按原文核查"
year: 2023
arxiv: "2304.08485"
version: "以已核实来源为准"
source: "实际原文链接"
code: "实际代码链接 / 未核实"
status: "已完成 / 进行中"
reviewed_on: "YYYY-MM-DD"
tags: [MLLM, paper-reading]
---
# 论文标题 — 精读笔记

> 阅读状态：已完成 / 进行中；证据等级 A 原文 / B 代码或旁证 / C 我的推断

## 一页速览
## 研究背景与必要前置知识
## 方法总览（架构图定位 + 数据流）
## 模块详解（表格含输入 / shape / 输出 / 参数冻结与更新）
## 关键公式与推导（LaTeX）
## 训练流程（含 loss、mask、梯度路径）
## 推理流程（含自回归 / 采样 / KV Cache 等适用细节）
## 实验、消融与证据审查
## 复现与代码对应（未检查则注明）
## 局限与后续工作
## Research Idea（必须写证据和创新性不确定性）
## 自测问题与术语表
## 参考链接与未核实清单
```

- 所有结论保留可回溯定位，如 `Section 3.2 / Eq. (4) / Table 2 / Page 5`；无真实证据不得编造定位、来源链接或数字。
- 公式用常规 Markdown LaTeX 定界符 `\(...\)`、`\[...\]` 或 `$$...$$`；代码用带语言标记的 fenced block，数据表格用标准 Markdown 表格。
- 允许链接原论文图表或给出图号；只有有权合法使用和可真实访问的图片才嵌入。文中绝不可插入捏造的模型图或声称复制了未看过的图。
- 如果论文对某细节没有写明，保留 `[论文未报告]`，如果附带代码或后续工作论证需标明来源。

## HTML 导出

使用本 Skill 内 `scripts/render_paper_html.py`：

```bash
python scripts/render_paper_html.py notes.md --output notes.html
```

要求：标题、侧边目录、移动端布局、打印样式、代码块、表格、明暗主题、正文图表和引用；使用内联 CSS 使 HTML 版可作为单文件浏览。LaTeX 公式由 MathJax CDN 在联网浏览器渲染；**离线浏览器仍能看正文，但可能只看到公式的 LaTeX 源码**。如用户要求完全离线公式，须采用离线依赖打包或预先渲染 SVG/MathML，不能声称本脚本天然保证离线公式渲染。

## 文件生成与校验

1. 先检查笔记是否覆盖用户要求的阅读范围并用准确来源支持关键声明。
2. 将最终 Markdown 写入实际工作目录，优先用户指定的位置；不要只发围栏中的 Markdown 后声称已经生成文件。
3. **始终生成 HTML**：由实际 Markdown 生成，生成后检查文件存在、编码、主要标题与结构，遇到渲染问题先修复再交付（用户明确说仅要 MD 或不要 HTML 除外）。
4. 双文件默认交付时保持对应内容一致，并确认两份都属于同一论文、同一版本，HTML 应来自该轮最新 Markdown。
5. 仅在确实已创建并验证实际文件时提供下载链接；若不能创建文件，明确说明限制并提供可复制文本。
