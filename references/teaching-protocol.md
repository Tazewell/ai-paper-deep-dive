# 深度教学协议（在数学/架构细节占比较高时使用）

## 阅读与拆解优先级

1. 先抓研究问题：旧方法何时失败、失败证据是什么、本文怎样设计对照。
2. 抓作者的模型总览图和算法框，将箭头变成**实际执行顺序**；核对每一条支路。
3. 给出**术语最小前置图**：学习此方法前必须知道的 3–6 个概念，附简短定义；非必要的基石论文不强迫先读。
4. 标注公式之间的推导依赖，逐符号翻译并解释为什么这样设计。
5. 给出一个端到端例子并明确标为教学构造，演示输入、内部形状、预测、损失与梯度。
6. 说明训练与推理的切换点（Teacher Forcing → 自回归，噪声预测 → 多步采样，offline trajectory → online rollout 等）。

## 模块说明卡片（每个重要模块）

- **解决的子问题：** 为什么这个模块必需？移除会怎样？
- **输入：** 真实表示（像素 / float embedding / 离散 token id / 时间状态等）和 shape。
- **操作：** 算子、注意力和信息交换方向、参数共享/冻结状态。
- **输出：** shape、物理/语义含义、下游依赖。
- **训练：** 哪些参数被更新，梯度来自哪里，mask 怎么配置。
- **推理：** 是否保留该模块、是否可缓存、是否引入多轮或搜索成本。
- **证据位置：** Section、Figure、Equation、Appendix 或代码地址。

## 公式拆解格式

给定核心公式，例如 `L = -\sum_t \log p_\theta(y_t | y_{<t}, x)`：

1. 说明 `x`, `y_t`, `\theta` 的含义和实际来源。
2. 标明这是 teacher-forced 目标，而不是输出阶段的采样策略。
3. 解释负对数似然怎么得到梯度、梯度可以更新哪些参数。
4. 补充 padding/user/prompt/image tokens 对 loss mask 的影响：必须以具体论文为准。
5. 如有必要，给出一个极小玩具序列示例与一行伪代码；不要把玩具参数当成作者的设置。

## 复杂内容的分层解释

- **直觉层**：一句日常类比 + 目标失败案例。
- **机制层**：流程图或分步算法、tensor 数据流与信息依赖。
- **数学层**：逐步推导、符号、假设与梯度。
- **工程层**：真实代码路径、计算成本、复现陷阱。
- **批判层**：设计代价、替代方案与可证伪假设。

解释中的每个图示都标明是原论文图、重绘示意还是抽象总结。不要把示意图误认作原文截图。
