# 输出模板与交互示例

## A. 默认精读报告（按论文灵活收缩/展开）

1. **论文身份证**：标题、年份/版本、机构/作者（经核查）、代码与数据链接、阅读范围。
2. **30 秒速览**：一句话目标、核心思路、主要贡献、最大限制。
3. **研究问题与前置知识**：为什么旧方法不够，必须掌握哪些基础概念。
4. **架构与方法详解**：端到端信息流图 + 每个模块的输入、运算、输出与原因。
5. **关键公式推导**：逐符号、维度、损失、梯度、数学假设与直觉。
6. **训练流程**：数据格式、步骤、冻结范围、更新参数、loss 与监督信号。
7. **推理流程**：初始化、prefill / stepwise decode / sampler / rollout 等实际执行流程。
8. **实验与消融**：数据、基线、公平比较、表格关键数字、结论支持范围。
9. **复现与代码**：官方实现定位、复现坑点和未知项。
10. **局限、批判与可延伸 idea**：明确区分猜想与已验证结论。
11. **复述与检查**：用三段话教读者讲给别人、3 个自测问题。

当输出过长时，应至少覆盖 1、2、4、6、7、8 的核心内容，不默默删掉；其余部分可分轮深入。用户显式要全套时应尽可能完整完成，而不是故意卡在目录。

## B. 分章节教学节奏

- 起始：直接给真实论文导图与讲解第一节；说明所依据版本。
- 中段：用户问具体问题，先回答，再依据上下文继续原进度。
- 深入：对有争议的公式，逐行推导，不把核心步骤省略成“由此可得”。
- 每节尾声：提出一个可验证的小问题或一行形状计算，不做冗余测验。

## C. 示例使用请求

- “帮我逐节精读 https://arxiv.org/abs/2304.08485，重点讲 LLaVA 的 alignment、instruction tuning、梯度流和推理。”
- “解释这篇论文 Section 3 Eq. (5)，每个符号都标出 shape，推导不要跳步。”
- “对照作者的 GitHub 代码告诉我 training forward、loss mask 和 inference decode 怎么实现。”
- “请用四张 48GB GPU 的限制，设计一个可复现这篇论文关键假设的最小实验。”
- “这个 idea 有人做过吗？寻找最相似的研究，告诉我科学假设和负对照是否成立。”
- “将读完的内容整理成附公式、图表定位、参考文献的 Markdown 研究笔记。”
- “请精读 LLaVA 并在完成后同时给我可下载的 Markdown 和 HTML 版，HTML 要有导航目录和公式。”

## D. 默认文件产出约定

整篇论文精读与逐章节精读**默认自动附上两份经验证的 `*.md` 与 `*.html` 文件下载链接**，无需用户再次要求或询问。分章节任务输出 `进行中` 状态笔记，完成整篇后改为 `已完成`；下一轮可访问旧文件时更新同一篇。用户明确不要文件时遵从。文件内容遵循 `references/archiving-and-export.md`，不得用聊天摘要替代论文原文核查。
